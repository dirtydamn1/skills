# 任务书规范（定时任务 / 被动执行）

定时任务、无人值守的收集任务，**执行时没有人可以问**。所以：任务书要在启动前定死一切口径，执行时不再向用户反问。

## 一、开工前必须向用户确认至少 1 次

创建定时任务、或开始收集工作之前，**必须向用户确认至少 1 次最终核对信息**——任务一旦进入被动执行（cron 触发、无人值守），**无法再与用户交互**，所有口径都必须在启动前定死。

核对清单（对着任务书的四段过一遍）：

- **【任务描述】**：时间窗（近 24 小时？近 2-3 天？含不含周末）；领域与地域偏好（国内/国际及占比）；条数与排序（默认 5–8 条、按热度）；兜底口径（确实没大事怎么回，默认「今日平静，无重大动态」，**禁止编造凑数**）
- **【台账参数】**：本批「类型」叫什么（早报 / 热点早报 / 晚报…）；「新闻类别标签」的填法（用户指定了领域 → 填领域；没指定 → 按 IPTC 多值）
- **【台账地址】**：飞书表格 URL + 写入哪张工作表 + sheet_id，逐字核对
- **【输出格式】**：默认只给「序号 + 一句话事实」

确认后把结果固化进任务书；被动执行时**不再反问用户**。

## 二、任务书必须写明的 5 项

1. **必须加载 `push-ledger` 技能** —— 任务书里写明技能名，保证执行时先加载技能再动手
2. **【任务描述】** —— 用户对任务的描述（领域、地域与占比要求、条数、排序、时间窗、兜底口径）
3. **【台账参数】** —— 「类型」= 什么；「新闻类别标签」列按 IPTC 多值填（中文分号分隔）；「题材类别」列填 IPTC 单值
4. **【台账地址】** —— 飞书表格 URL + 写入哪张工作表（通常是「当前」，可带 sheet_id）
5. **【输出格式】** —— 默认「只给序号 + 一句话事实」，不额外给类别、来源、热度说明、前言后记

## 三、任务书示例（标准模板）

```
每天 7:00 生成并推送「热点新闻早报」。按已加载的 push-ledger 技能执行。

# 任务描述
获取当天或最近社会热度或关注度要高的国内为主的或国际新闻，按热度排序取 5-8 条，国内的占比必须大于等于 70%，确实没大事就只回「今日平静，无重大动态」，不编造凑数。
时间窗 = 近 24 小时（可放宽到 2-3 天）；

# 台账参数
「类型」= 热点早报；
「新闻类别标签」列按 IPTC 多值填（中文分号分隔）；
「题材类别」列填 IPTC 单值

# 台账地址
https://xxxx.feishu.cn/sheets/xxxxxxx
写入「当前」工作表（sheet_id: xxxx）

# 输出格式
只给「序号 + 一句话事实」，不要类别、不要来源、不要热度说明、不要前言后记。
```

## 四、落地时别忘了

- 任务书里的**台账 URL / sheet_id 直接复制**，不要凭记忆手打
- 「类型」字段必须写死（交互流程里这一步是问用户的，被动执行时问不出来）
- 日期口径写死：`日期` 列填**推送日**还是**内容发生日**（跨零点最容易出错）
- 若任务要长期跑，把归档阈值/保留条数也写进任务书（默认 1000 行触发，保留最近 200 条）
- 任务跑完仍要按 SKILL.md 的工作流做**回读校验**；写不进去要在输出里显式报错，不要静默当成成功
